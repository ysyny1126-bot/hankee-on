# 프롬프트: 공공데이터 + 레시피 사이트로 정보 정확도 높이기

> 2026-11-24 작성. 아래 내용을 그대로 Claude에게 주면 같은 작업을 할 수 있다.
> 앞선 프롬프트(`docs/프롬프트_정보와정확성.md`)의 규칙을 그대로 지키고, 근거 자료를 바깥에서 가져오는 단계를 더한 것이다.

---

## 역할
너는 1인 가구 식생활 앱 '한끼온'(Expo/React Native)의 **식품 데이터 편집자 겸 개발자**다.
레시피·영양·보관 정보를 **확인할 수 있는 근거**로 다시 맞춘다.
모든 값에는 **어디서 왔는지(출처)**를 남긴다.

## 레시피 사이트 규칙(저작권·이용약관)
세 사이트의 레시피 글과 사진은 각 사이트와 작성자의 것이다. robots.txt로 막히지 않은 페이지라도 그대로 가져다 쓸 수는 없다.
- **하지 않는다**
  - 글·사진·영상을 복사해 앱에 넣는 것
  - 많은 페이지를 자동으로 긁어 오는 것(크롤링·대량 수집)
  - 사이트 이름이나 작성자 이름을 앱에 넣어 그 사이트 레시피처럼 보이게 하는 것
- **한다**
  - 메뉴 하나당 상위 레시피 **2~3개를 사람이 읽듯 열어** 다음만 숫자로 비교한다.
    - 재료의 양 범위(예: 1인분 간장 1~2큰술)
    - 불 세기와 시간 범위
    - 빠지기 쉬운 재료
  - 비교한 결과는 한끼온의 말로 **새로 쓴다.** 재료 비율 같은 사실은 쓰되, 문장은 쓰지 않는다.
  - 확인한 주소는 내부 기록(`docs/출처기록.md`)에만 남기고 앱 화면에는 넣지 않는다.
- 상업 서비스로 출시할 때 이 사이트들의 자료를 더 많이 쓰려면 **이용약관을 사용자가 먼저 확인**한다. 필요하면 제휴나 허락을 받는다. Claude는 약관을 대신 판단하지 않고 물어본다.

## 정확도 판단 규칙
1. **공공데이터가 기준이다.** 공공데이터와 레시피 사이트가 다르면 공공데이터를 따른다.
2. **공공데이터에 없는 메뉴**는 레시피 사이트 2~3곳의 **공통 범위**를 쓴다. 범위 밖으로 튀는 값 하나는 버린다.
3. 1인분으로 바꿀 때는 원래 양 ÷ 인분 수로 나눈 뒤, 계량하기 쉬운 단위로 반올림한다(0.5큰술 단위, 10g 단위).
4. 안전 기준은 항상 식약처 기준을 쓴다(고기 중심온도 75℃에서 1분 이상, 조리 음식은 2시간 안에 냉장).
5. 근거를 찾지 못한 값은 지어내지 않는다. 비워 두거나 '참고값(추정)'으로 표시한다.
6. 모든 레시피·재료 항목에 `source` 필드를 단다. 값은 `'식약처 레시피DB' | '식약처 영양DB' | '식약처 보관' | '사이트 비교' | '한끼온 추정'` 중 하나다. 화면에는 작은 글씨로 '근거: 식약처 DB'처럼 보여 준다.

## 진행 순서
1. **키 준비**(사용자 할 일, 무료)
   - 식품안전나라 Open API 키와 공공데이터포털 '식품영양성분DB정보' 키를 받는다.
   - 사용자는 키를 **복사만** 한다. Claude가 클립보드에서 읽어 `.env`에 저장하고, 값은 화면에 출력하지 않는다. `.env`는 커밋하지 않는다.
2. **가져오기 스크립트**: `scripts/fetch-public-data.mjs`를 만든다.
   - 지금 레시피 69개의 이름으로 레시피 DB와 영양 DB를 찾아 `데이터/공공데이터/2026-11-24_원본.json`에 저장한다. 이 파일은 git에 올리지 않는다.
   - 요청은 천천히 보낸다(초당 1회 이하). API 호출 한도를 넘지 않는다.
3. **대조표 만들기**: `docs/출처기록.md`에 레시피마다 한 줄씩 적는다.
   - 지금 값 / 공공데이터 값 / 사이트 비교 범위 / 결정 / 근거
   - 차이가 큰 항목(양 50% 이상, 시간 5분 이상 차이)만 표시해 사용자에게 먼저 보여 준다.
4. **고치기**
   - `recipes.ts`·`keep.ts`·`units.ts`·영양 참고값을 대조표대로 고치고 `source`를 단다.
   - 영양값은 식약처 DB 값으로 바꾼다. 맞는 음식이 없으면 비워 둔다.
5. **점검**
   - `scripts/check-recipes.mjs`에 검사 두 가지를 더한다.
     - 모든 항목에 `source`가 있는지
     - `'한끼온 추정'`이 몇 개 남았는지 개수
   - 타입 검사와 코드 검사를 돌린다. iOS 시뮬레이터에서 레시피 화면의 '근거' 표시를 스크린샷으로 확인한다.
6. **기록**: 작업일지를 쓰고 커밋·푸시한다. 원본 데이터와 키는 올리지 않는다.

## 화면에 보여 주는 방법(난잡하지 않게)
- 레시피 화면 맨 아래에 한 줄을 둔다: '근거: 식약처 레시피 DB · 1인분으로 다시 계산'
- 영양 배지는 식약처 DB 값이면 '(추정)'을 떼고, 아니면 지금처럼 '(추정)'을 둔다.
- 보관 안내의 '식약처·USDA 참고' 문구는 항목마다 실제 근거로 바꾼다.

## 하지 말 것
- 레시피 사이트의 글·사진 복사, 대량 수집, 사이트 이름을 앱에 노출
- 키·토큰 값을 출력하거나 커밋

- 근거 없이 '정확함', '검증됨' 표시
