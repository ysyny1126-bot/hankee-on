# 프롬프트: 메뉴 분류 + 깔끔한 추천 리스트

> 2026-11-24 작성. 레퍼런스 2장(카테고리 격자형 레시피 목록, 종류·상황·재료·방법별 다단 필터 레시피 사이트)을 참고하되 그대로 옮기지 않는다.
> 아래 내용을 그대로 Claude에게 주면 같은 작업을 할 수 있다.

---

## 역할
너는 1인 가구 식생활 앱 '한끼온'(Expo/React Native, Expo Router)의 UX 디자이너 겸 개발자다.
사용자가 "오늘은 이런 걸 먹어 보고 싶다", "새로운 걸 도전해 보고 싶다"고 할 때 **분류에서 골라 바로 추천을 받는** 화면을 만든다.
핵심은 **정보를 적게 보여 주는 것**이다. 고르는 단계는 최대 2번, 한 번에 보이는 추천은 최대 3개다.

## 레퍼런스에서 가져올 것 / 가져오지 않을 것
| | 가져올 것 | 가져오지 않을 것 |
|---|---|---|
| 격자형 카테고리(1번 이미지) | 한눈에 보이는 **칸 격자**, 고른 칸만 진하게 | 19칸짜리 긴 목록, 갈색 톤, 영문 장식 제목 |
| 다단 필터(2번 이미지) | **'무엇을'과 '어떤 상황'을 나눠 고르는** 구조 | 4~5줄 필터, 수십 개 칩, 총 개수·정렬 탭, 큰 사진 4열 |
| 공통 | 고른 조건이 바로 결과에 반영됨 | 광고·랭킹·인플루언서 같은 부가 메뉴 |

한끼온에 맞게 다시 푼다.
- 색은 지금 브랜드 초록 하나와 `art` 그림 색만 쓴다.
- 칸 안에는 이모지 + 짧은 이름 + 개수를 넣는다.
- 1인분, 자취 부엌 기준을 지킨다.

## 분류 체계(고정 · 레시피마다 태그 정리)
1. **무엇을(종류) — 8칸, 한 레시피에 하나만**
   - 🍲 국·찌개 · 🍳 볶음·구이 · 🍚 밥·덮밥 · 🍜 면 · 🥢 반찬 · 🥪 간편식 · 🍝 양식 · 🌶️ 분식
2. **어떤 상황 — 6개, 한 레시피에 여러 개 가능**
   - ⚡ 10분 컷: 조리 시간 15분 이하에서 자동으로 정한다
   - 🍱 도시락
   - 🥗 가볍게: 채소가 많거나 칼로리가 낮은 것
   - 🍺 야식·안주
   - 💪 든든하게: 단백질이 많은 것
   - 🔥 도전 요리: 난이도 '보통' 이상이거나 처음 만드는 메뉴
3. **재료별은 따로 만들지 않는다.** 이미 '냉장고 털기'와 재료 검색이 있다.
4. **지금 태그 정리**
   - 지금 레시피 태그(한식·초간단·국물·볶음 등 20종)를 위 체계로 바꾸는 표를 만든다.
   - 자동 점검 스크립트(`scripts/check-recipes.mjs`)에 다음 검사를 더한다.
     - 모든 레시피가 **종류 하나**를 가졌는지
     - 모든 레시피가 **상황 하나 이상**을 가졌는지
   - 레시피가 3개 미만인 칸은 화면에 보이지 않게 숨긴다.

## 화면 흐름(메뉴 탭 안, 새 탭을 만들지 않음)
1. **메뉴 탭 맨 위에 '뭐 먹고 싶어요?' 격자**
   - 종류 8칸을 4×2로 놓는다.
   - 칸에는 이모지, 이름, '내 재료로 n개'를 표시한다.
   - 아무것도 안 골랐을 때는 지금 화면(오늘 추천)을 그대로 둔다.
2. **칸을 고르면 아래에 상황 칩 한 줄**
   - 가로로 넘기는 한 줄이고, 고르는 건 선택이다.
   - 고른 조건은 '국·찌개 · 10분 컷 ✕'처럼 한 줄 요약으로 보여 준다. ✕를 누르면 지운다.
3. **추천 리스트**
   - 처음에는 **3개만** 보여 준다.
   - 카드 한 장에 넣는 것
     - 이모지, 이름, 시간·난이도 한 줄
     - **추천 이유 한 줄**: '내 재료로 바로 · 먼저 쓸 대파 사용' / '재료 1개만 사면 돼요' / '처음 도전해요'
   - 카드에서 뺄 것: 영양, 재료 목록 전체, 사진 여러 장, 작성자
   - 아래에 '3개 더 보기'를 두고, 한 번에 3개씩 늘린다. 끝까지 보면 '다른 칸 보기'를 띄운다.
4. **추천 순서(한 줄 이유와 같은 근거)**
   1. 알레르기·기피 음식이 든 메뉴는 아예 뺀다(지금 규칙 그대로).
   2. 지금 재료로 바로 만들 수 있는 것을 먼저, 부족한 재료가 적은 순으로 놓는다.
   3. 먼저 쓸 재료(기한 임박)를 쓰는 메뉴에 가산점을 준다.
   4. '도전 요리'를 골랐다면 한 번도 안 만든 메뉴를 먼저 놓는다. 아니면 최근 3일 안에 만든 메뉴를 뒤로 보낸다.
   5. 지금 쓰는 추천 점수(`rankForUser`·`recommend.ts`)를 다시 쓰고, 분류 필터만 앞에 더한다.
5. **빈 결과**
   - "이 조건엔 아직 메뉴가 없어요"와 함께 조건 하나를 풀자는 버튼 하나를 띄운다.
   - AI가 켜져 있으면 'AI로 만들어 보기' 버튼 하나를 더한다.

## 정보량 규칙(난잡하지 않게)
- 한 화면에 고르는 줄은 **격자 1개 + 칩 1줄**까지만 둔다.
- 처음 보이는 추천 카드는 **최대 3개**다.
- 카드 안 글자는 **두 줄 이내**다(이름 / 시간·이유).
- 숫자는 '내 재료로 n개' 하나만 쓴다. 총 레시피 수, 정렬 탭, 랭킹은 넣지 않는다.
- 모든 칸과 칩은 누르는 영역 44pt 이상, 화면낭독기 이름표를 단다.

## 진행 순서
1. 태그 → 분류 바꿈 표를 만들고 `recipes.ts`에 `kind`(종류)와 `moods`(상황) 필드를 채운다. 점검 스크립트 검사를 추가한다.
2. `src/logic/browse.ts`를 만든다: 분류별 개수, 필터, 추천 순서, 한 줄 이유.
3. 메뉴 탭에 격자, 칩, 추천 리스트를 붙인다. 지금 필터(먼저 쓸 재료·15분 이내·냉장고 털기·즐겨찾기)와 겹치는 것은 정리한다. 15분 이내는 '10분 컷'과 합친다.
4. 타입 검사, 코드 검사, `npm run check:data`를 돌린다. iOS 시뮬레이터 스크린샷으로 격자, 칩 선택, 추천 3개, 더 보기를 확인한다.
5. 작업일지를 쓰고 커밋·푸시한다.

## 하지 말 것
- 레퍼런스 화면의 색·문구·배치를 그대로 옮기기
- 필터 줄을 3줄 이상 만들기
- 새 라이브러리 설치(필요하면 먼저 묻기)
- 레시피 수를 늘리려고 확인 안 된 레시피를 지어내기(늘릴 땐 정확도 프롬프트 `docs/프롬프트_정보와정확성.md` 규칙을 따른다)
